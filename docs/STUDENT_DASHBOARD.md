# IndicLearn Student Learning Dashboard & Visual Knowledge Map (Phase 8)

## 1. Overview & Research Philosophy

The **IndicLearn Student Learning Dashboard** serves as the primary presentation and interaction layer (Phase 8) for the IndicLearn intelligent tutoring research platform.

### Core Architectural Principle: Strict View Decoupling

The frontend functions purely as an explainable **VIEW** over the verified backend research architecture:

```text
                        BACKEND RESEARCH DOMAIN
                                   │
          ┌────────────────────────┼────────────────────────┐
          ▼                        ▼                        ▼
Academic Knowledge Graph  Student Knowledge Model  Personalized Recommender
   (NetworkX Store)     (KnowledgeStateService)    (RecommendationService)
          │                        │                        │
          └────────────────────────┼────────────────────────┘
                                   ▼
                    Adaptive Assessment Core (7A)
                                   │
                                   ▼
                      API / Application Layer
                  (DashboardApplicationService)
                                   │  (REST / FastAPI)
                                   ▼
                       Student Dashboard SPA
                    (HTML5 / Vanilla CSS / JS)
```

The frontend **never** independently computes:
* Knowledge scores or confidence values
* Categorical mastery statuses (`MASTERED`, `DEVELOPING`, `EMERGING`, `UNCERTAIN`, `UNKNOWN`)
* Recommendation priority scores or pedagogical actions
* Adaptive assessment item sequences or difficulty tiers

All values originate directly from backend domain services.

### Epistemic Humility & Non-Deficit Communication

In accordance with human-computer interaction and educational psychology principles, the dashboard communicates estimated states rather than psychological certainties:
* Uses phrases such as **"Estimated knowledge"** and **"Evidence confidence"** instead of dogmatic claims like *"You know this concept."*
* Clearly informs the student that status categories represent mathematical model estimates derived from available interaction logs.
* Explicitly distinguishes **uncertainty** (insufficient evidence or conflicting quiz outcomes) from **deficit** (consistent demonstrated difficulty).

## 2. Interactive Academic Knowledge Map

The Knowledge Map renders an interactive 2D visualization of the academic curriculum:

* **Rendering Engine:** Native vector SVG with procedural topological layout based on prerequisite DAG depth and relaxed horizontal ranks.
* **Nodes:** Display concept canonical name, concept type badge, categorical status ring, and current estimated knowledge percentage.
* **Edges:** Render directed curves with SVG arrow markers distinguishing relation types:
  * `PREREQUISITE_OF` (accent indigo with directional arrow)
  * `PART_OF` (emerald directional arrow)
  * `RELATED_TO` (muted dashed line)
* **Interaction:** Supports drag-to-pan, mousewheel zoom, dedicated zoom control buttons (+ / − / Reset), and node selection.
* **Accessibility Fallback:** Features an accessible **List View** toggle presenting all curriculum concepts in a semantic HTML table with focusable inspection buttons, ensuring complete keyboard, screen-reader, and non-visual navigability.

### Visual Status Semantics

| Status | Color Token | Border Style | Meaning |
| :--- | :--- | :--- | :--- |
| `MASTERED` | Emerald (`#10b981`) | Solid ring | Strong positive evidence ($S \ge 0.75, C \ge 0.60$) |
| `DEVELOPING` | Sapphire (`#3b82f6`) | Solid ring | Moderate competency ($S \ge 0.50, C \ge 0.40$) |
| `EMERGING` | Warm Amber (`#f59e0b`) | Solid ring | Demonstrating difficulty or nascent signal |
| `UNCERTAIN` | Magenta (`#ec4899`) | Dashed / Glowing | Conflicting evaluation outcomes or high variance |
| `UNKNOWN` | Slate Muted (`#64748b`) | Faint ring | Zero or negligible interaction evidence |

## 3. Concept Detail Drawer & Evidence Transparency

Clicking any concept node or table row opens the Concept Detail Drawer:

1. **Curriculum Information:** Displays canonical name, concept type (`concept`, `method`, `property`), academic definition, and interactive prerequisite / dependent concept tags.
2. **Student Knowledge State:** Presents animated progress meters for estimated knowledge and evidence confidence, categorical mastery status, total evidence count, and strong vs. weak evidence counters.
3. **"Why this estimate?" Transparency Accordion:**
   * Explains the mathematical rationale generated by `KnowledgeStateService.explain_concept_state()`.
   * Details historical evidence events with timestamp, event type, evidence strength (`STRONG` assessment vs. `WEAK` interaction), and score.
   * Discloses the weighting policy: *Assessment events (quizzes) carry stronger weight than passive interaction events.*
4. **Curriculum Actions:** Direct shortcuts to [Inspect Source Material] or [Assess This Concept].

---

## 4. Personalized Recommendations Integration

The Recommendations section consumes the prioritized candidates generated by Phase 7B `RecommendationService`:

* **Recommendation Cards:** Display concept name, action badge (`REVIEW_CONCEPT`, `PRACTICE_CONCEPT`, `TAKE_ASSESSMENT`, `REVIEW_PREREQUISITE`, `REVISIT_SOURCE`), calculated priority score, and human-readable reason bullets.
* **Action Dispatch:**
  * Clicking **Take Assessment** automatically launches an adaptive assessment session for that concept.
  * Clicking **Review Concept** or **Inspect Material** opens grounded source textbook material.
  * Clicking **Map** centers the graph canvas and highlights the target node.
* **Zero Client Heuristics:** The frontend does not filter, re-rank, or alter recommendation scores.

---

## 5. Adaptive Assessment Interface

The assessment modal interfaces directly with Phase 7A `AdaptiveAssessmentService`:

* **Item Selection:** Delegated completely to the backend. The backend chooses the question based on student weakness, uncertainty, prerequisite needs, and difficulty tier.
* **Supported Item Types:** Deterministically grades Multiple Choice (MCQ) and True/False items.
* **Multilingual Assessment:** Features a real-time language selector supporting English (`en`), Telugu (`te`), Romanized Telugu (`te-Latn`), and Telugu-English Code-Mix (`te-en`).
* **Closed-Loop Feedback:** Upon submitting an answer:
  1. The answer is sent to `POST /api/assessment/sessions/{session_id}/responses`.
  2. The backend grades the answer, emits an `EvidenceEvent`, updates the evidence-weighted knowledge state, and selects the next adaptive question.
  3. The modal displays immediate pedagogical feedback and shows updated estimated scores and confidence.
  4. Closing the session automatically triggers a full refresh of the dashboard metrics, knowledge map, and recommendations.

---

## 6. RAG / Source Material Inspector

* **Provenance Preservation:** When examining recommended reading, the Source Material Modal displays the grounded textbook excerpt, document ID (`doc_signals_notes`), and verified page/section numbers (`Page 1 \| Section: LTI Systems and Convolution`).
* **Honest Missing-Source Handling:** If a concept does not have an indexed textbook chunk, the UI displays an explicit `Source unavailable` notice rather than fabricating citations or showing empty modals.

## 7. REST API Endpoints Specification

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/api/subjects` | List academic subjects with concept/relation counts. |
| `GET` | `/api/subjects/{subject_id}/graph` | Retrieve complete academic graph with student knowledge overlay. |
| `GET` | `/api/concepts` | List all curriculum concepts for a subject. |
| `GET` | `/api/concepts/{concept_id}` | Granular concept view with student state, prereqs, and recommendation. |
| `GET` | `/api/students/{student_id}/dashboard` | Learning analytics overview metrics (mean score, confidence, distribution). |
| `GET` | `/api/students/{student_id}/recommendations` | Top-$K$ prioritized personalized recommendation cards. |
| `POST` | `/api/assessment/sessions` | Initiate an adaptive assessment session. |
| `POST` | `/api/assessment/sessions/{session_id}/responses` | Submit answer, evaluate, update student model, and get next item. |
| `GET` | `/api/assessment/sessions/{session_id}` | Retrieve current state of an active assessment session. |
| `GET` | `/api/chunks/{chunk_id}` | Grounded curriculum chunk text, document ID, and page citation. |
| `POST` | `/api/demo/load` | Load isolated synthetic demonstration logs for UI testing. |

## 8. Evaluation Benchmark (EXP-009)

The presentation layer is validated by **EXP-009**, which tests 15 controlled software engineering and interface invariants:

1. `SCEN_001_KNOWLEDGE_GRAPH_RENDERS`: Canonical nodes and directed edges render correctly.
2. `SCEN_002_CONCEPT_DETAIL_LOADS`: Concept drawer loads academic prerequisites, dependents, and metadata.
3. `SCEN_003_STUDENT_STATE_OVERLAY`: Assessed student knowledge state reflects backend calculations accurately.
4. `SCEN_004_UNKNOWN_STATE_REPRESENTATION`: Fresh concepts show `UNKNOWN` status without false deficits.
5. `SCEN_005_UNCERTAIN_STATE_REPRESENTATION`: Conflicting quiz outcomes map to `UNCERTAIN` with transparency flag.
6. `SCEN_006_RECOMMENDATION_MATCHING`: Cards match Phase 7B planner output in count, priority, and actions.
7. `SCEN_007_ASSESSMENT_DELEGATION`: Starting assessment delegates question selection to Phase 7A.
8. `SCEN_008_ASSESSMENT_RESPONSE_SUBMISSION`: Student answers reach backend evaluator and yield feedback.
9. `SCEN_009_DYNAMIC_STATE_REFRESH`: Updated knowledge scores are immediately visible in subsequent queries.
10. `SCEN_010_SOURCE_PROVENANCE_PRESERVED`: Grounded chunk text, document ID, and page numbers are preserved.
11. `SCEN_011_MISSING_SOURCE_HONESTY`: Missing chunks yield structured 404s and explicit UI warnings.
12. `SCEN_012_STUDENT_ISOLATION`: Updates to Student A never mutate Student B's knowledge state.
13. `SCEN_013_EMPTY_STATE_HANDLING`: Fresh zero-evidence profiles return graceful empty state metrics.
14. `SCEN_014_BACKEND_ERROR_HANDLING`: Invalid concept or session IDs return clean 404s without server crashes.
15. `SCEN_015_DETERMINISTIC_API_MAPPING`: Repeated identical queries yield bitwise deterministic JSON schemas.

**EXP-009 Benchmark Outcome:** 15/15 scenarios passed (100.0%).

## 9. Limitations & Research Boundaries

1. **No Human Student Usability Study:** The interface has been rigorously validated against software contracts and automated scenarios; real human-subjects usability and cognitive load studies have not yet been conducted.
2. **No Empirical Learning Gain Claims:** The dashboard displays model-estimated indicators; it does not claim to statistically accelerate learning or improve test scores.
3. **Authentication Boundary:** For this research prototype, student isolation is enforced via explicit `student_id` API parameterization. Production deployment requires enterprise authentication (e.g., OAuth2 / JWT).
4. **Heuristic Student Model Limitations:** The underlying student knowledge model uses configurable evidence-weighted updates, confidence updates, and exponential recency decay rather than a parameterized IRT, BKT, or Deep Knowledge Tracing (DKT) model.
